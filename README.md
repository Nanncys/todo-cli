# todo-cli

一个用 Python 写的命令行待办事项管理器。先建「备忘录」，再往备忘录里加「待办项目」，支持标记完成、一键清除已完成项。

无第三方依赖，只用标准库。

## 功能

| 序号 | 功能 |
| :--- | :--- |
| `0` | 创建一个备忘录 |
| `1` | 查看备忘录列表 |
| `2` | 删除一个备忘录 |
| `3` | 进入一个备忘录，查看其中的项目列表 |
| `4` | 添加项目 |
| `5` | 删除项目 |
| `6` | 将项目设定为已完成 |
| `7` | 一键清除已完成项目 |
| `-1` | 退出 |

每次操作内部也支持输入 `-1` 中途退出。

## 运行

需要 Python 3.7+。

唯一的门槛是 `datetime.fromisoformat()`——3.7 才有。其余用到的都是很基础的语法：f-string（3.6+）、列表推导、切片。代码里没有用新版特有的写法，老版本可以放心跑。

```bash
python main.py
```

数据保存在同目录的 `text.json`，首次运行会自动创建。文件损坏时不会直接报错，而是把坏文件改名成 `text.json.broken_<时间戳>` 备份，再新建一个空文件。

## 项目结构

三层结构，自上而下单向依赖：

```
main.py       UI 层      输入输出、菜单、提示语
   ↓
todo.py       业务逻辑层  备忘录/待办的增删改查规则
   ↓
storage.py    存储层      读写 JSON 文件、处理文件异常
```

分层的判断标准（可以当成检验规则用）：

- `main.py` 是**唯一**允许出现 `input()` 和 `print()` 的文件；
- `todo.py` 和 `main.py` 里**不出现** `json`、`open`——它们不知道数据存在哪、怎么存；
- `storage.py` 里**不出现**「备忘录」「待办」这类业务词汇——它不认识业务概念，只认识「一个数据字典」。

一句话检验：把 `todo.py` 拿到一个没有屏幕的环境里去跑，它还能工作吗？

## 数据结构

```json
{
  "memo": [
    {
      "id": 1,
      "name": "学习计划",
      "create_time": "2026-09-20T15:30:22",
      "include": [
        {
          "id": 1,
          "create_time": "2026-09-20T15:30:22",
          "dead_time": "2026-09-21T15:30:22",
          "content": "背英语单词",
          "done": false
        }
      ]
    }
  ]
}
```

要点：

- 顶层是一个字典，只有一个键 `memo`，值是一个列表。以后要加「标签」这类新维度，直接加平级的新键，不用动现有结构。
- 备忘录的 id 全局唯一；待办的 id 只在**所属备忘录内部**唯一，所以不同备忘录里的待办 id 可以重复。
- 时间统一用 ISO 8601 字符串（`datetime.now().isoformat()` 的产物），可读、可直接比较、JSON 里是原生字符串。
- `dead_time` 只接受 ISO 格式，且不能是过去时间，由 `main.py` 在输入时校验。

## 已知取舍

- **id 用 `max(id) + 1` 生成**。删除中间项后再新增，id 会被复用。当前场景够用，迁移到 SQLite 后由 `AUTOINCREMENT` 接管。
- **数据文件进了版本控制**。`text.json`（运行时数据）和两个 `text.json.broken_*`（损坏备份）目前都被 git 跟踪，这更像本地数据而不是项目源码。另外 `t.json` 是最初设计 JSON 结构时留下的示例文件，内容与上面「数据结构」一节一致，程序并不读它——格式示例已经写进本文档，这个文件可以删掉。后续应该把它们从跟踪里移除（`git rm --cached`）并写进 `.gitignore`。
- **每次操作要读 2 次文件**。例如「查看项目列表」先后调用了 `get_todo_list` 和 `get_memo_name`，各自 `load_data()` 一次。数据量大或改成数据库后值得合并成一个访问器。

## 路线图

- [x] JSON 文件存储
- [ ] 迁移到 SQLite
- [ ] 数据文件移出版本控制

关于 SQLite 迁移有一个待决策的分叉：是保持现在的 `load_data` / `save_data` 整块读写接口（`todo.py` 一行不用改，但用不上 SQLite 的按行操作和条件查询），还是让 `storage.py` 提供细粒度的增删改查接口（`todo.py` 要重写，但 `clean_todo_done` 会从一整个函数塌缩成一句 `DELETE FROM todo WHERE memo_id = ? AND done = 1`）。
